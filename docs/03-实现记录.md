- **D10**：方案 B——运行时 SQLite，demo 数据 CSV 启动导入。

## 五、题目集合沿革（demo）

题面内容换过两轮，最终在 v1.4 收敛为单题：

| 阶段 | 题目 | 说明 |
|---|---|---|
| 初版 | ScratchV 算子题 fwht / conv / spmv | 平台刚搭建时的占位 |
| v1.1 | LeetCode 三题（两数相加 / 无重复字符的最长子串 / 最长回文子串） | 换成通用算法题 |
| v1.4 | `matmul-4x4` 单题 | 收敛为与评测能力一致的一道 RISC-V 题 |
| **v1.5（当前）** | **`add` / `matmul-4x4` / `reducesum` 三题** | 按用户指定扩展为三题，范围可评测 |

- **v1.4 下线 LeetCode 三题的原因**：它们只有题面、没有评测能力（`submittable=False`），
  与"提交 → qemu 评测"的主线不一致，容易误导选手。
- **同步改动**：`problems.py` 只留 `matmul-4x4`；`index/_rail/problems/help` 的
  文案与评分口径改为"单题满分 100、按动态指令数计分"；`standings.py` 文档
  去掉了"3 题 300 分"的说法。
- **demo 榜单数据**：重建为 26 条提交（7 队 × 3 题），队伍名换成 RISC-V 主题
  （旧队伍名如"回文猎手""滑动窗口炼丹"是 LeetCode 题面衍生，一并更换）。
- **v1.10 起**：演示数据由 `tools/gen_demo_data.py` 生成，**含逐数据点原始代价**，
  且**不存分数**——分数由榜单按动态基准现算，与真实提交走完全相同的链路。
  各队有不同的"能力曲线"（有的小 N 强、大 N 崩），这样逐数据点视图才有内容可看。

## 一、功能介绍

### 1.1 功能概述

P3 把平台推进到**"提交补丁 → 固定赛题编译/仿真 → 正确性 + 性能判定 → 结果与配额"**的完整闭环。选手**不改写题目算法**，而是**改造 ScratchV 编译器本身**（新增/修改算子代码生成、优化 pass、寄存器分配等），让同一道固定赛题生成更快且数值正确的机器码。

- **提交**：登录并入队的选手在 `/submit` 选择赛题、上传一个 **补丁文件**（`git diff`/`git format-patch` 产物，`.patch`/`.diff`）；平台校验配额后建记录、入队。
- **评测流水线**（后台 worker）：
  1. 取**冻结基线**版 ScratchV（固定 commit）到临时工作副本；
  2. `git apply` 选手补丁（**仅允许改动编译器源码路径**，见 D18）；
  3. 用**可信测量副本**对固定赛题的 ONNX 模型编译并仿真（`RV32EmulatorFast`，`--uarch basic`，`--max-instr` 上限）；
  4. 与独立 NumPy 参考执行器比对（Q16.16，容差 ≤1 LSB），得正确性；
  5. 汇总性能指标（`dynamic_instructions` / `total_cycles` / `cpi` / `code_size`），按计分策略算分；
  6. 清理临时副本。
- **结果详情** `/result/<id>`：verdict 徽章、正确性（max_lsb / 输出形状）、分数据点性能表、补丁 diff（转义展示），非终态轮询、终态停止。
- **配额**：每队每日 99 次，05:00（UTC+8）重置；耗尽禁用提交。

> **与 demo 的关系**：公开演示站仍用 LeetCode 三题的安全桩（不执行选手代码）；真实赛道走本设计。二者共用一套 UI/契约/状态机，**不强行统一口径**（用户 2026-10-01 明确）。

### 1.2 设计目标

- **补丁即提交、赛题固定**：选手产出物可复现（补丁 + 基线版本 = 完整可重放）；同一补丁在任何时间跑出同一结果。
- **测量与产测分离（可信边界）**：编译用打补丁的编译器，但**性能计数与数值比对必须由未打补丁的可信代码完成**——否则选手可改 `benchmark.py` 让周期数变小。这是本设计的**安全基线**（D19）。
- **契约先行**：先冻结 verdict 状态机、`details` JSON、计分策略、补丁路径面，前后端并行。
- **后端可插拔**：`evaluator.py` 只做门面；`backends/scratchv_patch.py` 负责真实评测，`backends/stub.py` 供无环境时演示/联调。
- **多指标、后定权**：cycles / instructions / cpi / code_size / ratio（相对基线）全部留存，`score` 由可配置策略计算（D12）。
- **失败可见可操作**：补丁应用失败、编译失败、正确性失败、超时、仿真异常都要落到明确 verdict。
- **零构建、移动优先、深浅色等价**：沿用已落地的 `base.html` 与设计 token。

### 2.3 Verdict 状态机

```
pending ──► running ──┬─► accepted        正确性通过 + 计分成功
                      ├─► compile_error   补丁应用失败 / ScratchV 代码生成失败
                      ├─► timeout         编译或仿真超过预算
                      ├─► runtime_error   仿真/工具链异常
                      └─► invalid         正确性与参考不符（一票否决）
```

| verdict | 文案 | 徽章类 | 计入榜单 |
|---|---|---|---|
| `pending` / `running` | 排队中 / 评测中（spinner） | `.vbadge-pending` | 否 |
| `accepted` | 通过（得分 X） | `.vbadge-accepted` | 是 |
| `compile_error` | 补丁/编译失败 | `.vbadge-error` | 否 |
| `timeout` | 超时 | `.vbadge-warn` | 否 |
| `runtime_error` | 运行错误 | `.vbadge-error` | 否 |
| `invalid` | 正确性未通过 | `.vbadge-critical` | 否 |

- 补丁 `git apply` 失败并入 `compile_error`（`details.stage="apply"`）；`wrong_answer` 并入 `invalid`。
- 终态集合 = `{accepted, compile_error, timeout, runtime_error, invalid}`；轮询到终态即停。

### 2.4 计分口径（多指标留存，权重后定 D12）

单次评测产出：

| 指标 | 来源 | 用途 |
|---|---|---|
| `dynamic_instructions` | `PerfCounters.total` | 主指标候选（与规模弱相关，最稳定） |
| `total_cycles` | `PerfCounters.total_cycles`（uarch profile） | 主指标候选 |
| `cpi` | 周期/指令 | 展示 / 辅助 |
| `code_size` | 代码段字节 / 静态指令 | 展示 / 辅助 |
| `max_lsb` | 与 NumPy 参考的最大绝对误差 | 正确性门禁 |
| `ratio = baseline / patched` | 同指标基线比值 | 加速比（多指标各自算） |

- **门禁**：`max_lsb <= tol_lsb`（默认 1）且非 `size_mismatch`，否则 `invalid`（一票否决）。
- **得分策略（可配置，默认占位）**：`score = 100 × min(1, baseline_cycles / patched_cycles)`；指令/CPI 等同步留存。**最终以哪个指标、是否多指标加权，由主办商定后只改配置，不改流水线**（D12）。
- **超时判定**：编译或仿真超过 `EVAL_TIMEOUT`，或动态指令超 `max_instr` 上限 → `timeout`。
- 正确性未过不计入任何最优。

### 2.5 评测后端与 `details` 契约（D11 核心）

**统一接口**

```python
def run_evaluation(submission_id, team_name, problem_id, code_path, meta=None) -> tuple[float, dict]:
    """返回 (score, details)。后端由 judge.backend 选择（auto/scratchv_patch/stub）。"""
```

**`backends/scratchv_patch.py` 流水线**

```
temp_workdir/
├── base/            # git worktree/clone --detach <baseline_ref>（冻结版本）
├── apply.patch      # 选手补丁
└── run/             # 可信测量副本（未打补丁的 benchmark/verifier）

1) git -C base apply --check apply.patch      # 失败 → compile_error(stage=apply)
2) git -C base apply apply.patch
3) 校验改动路径面：git -C base diff --name-only <baseline_ref> 必须全部落在
   允许集合内、且不含禁止集合（D18/D19）→ 违规 → compile_error(stage=scope)
4) 编译：PYTHONPATH=base python3.11 <base>/scratchv/standalone/onnx_to_riscv_standalone.py
         <模型> -o out.bin --asm out.s [--max-instr N]
5) 仿真 + 比对：用 run/ 下的可信 verify_model 逻辑（可信的 benchmark/emulator），
   以 base 为编译源、以 **可信副本** 为测量源（见 D19），得 max_lsb / 指标
6) 清理 temp_workdir
```

### 2.7 查询守卫：防止"永远 running"

- worker 异常必须落终态（`runtime_error`）；`details` 带 `stage` 便于定位。
- 结果页轮询退避 2s→4s→8s（上限 30s）；超过 `EVAL_TIMEOUT + 30s` 未终态 → 展示"评测长时间未完成"+ 提交编号。
- 启动时把 `status in (pending, running)` 且 `updated_at` 过期的记录标 `runtime_error`（防重启僵尸态）。

### 2.10 性能杠杆分析与补丁路径面（D18 依据）

> 结论来自对 `/root/Lab/ScratchV`（`6fcb97b`）的代码走读，行号为该版本快照。

**关键事实：生产路径 = `scratchv/standalone/onnx_to_riscv_standalone.py`（自带 protobuf 解析、`MemoryPlan`、`RISCVEmitter`、`CNNRISCVGenerator`，直接产 RV32IM 机器码）。** 它**只 import 标准库**，不 import `optimizer/`、`ir/`、`pass_interface.py`、`frontend/`；后四者是 `compiler.py`/`main.py` 的 DSL→IR 路径专用。→ **开放它们对固定 ONNX 赛题零收益，必须明确禁止（避免误导选手改不可达代码）。**

**各算子的性能杠杆（按可优化空间排序）**

| 位置（`onnx_to_riscv_standalone.py`） | 现状每 MAC/元素的指令开销 | 可优化点 | 杠杆 |
|---|---|---|---|
| `_gen_conv` 带 pad 通用路径（1935–2002） | **~25–30 条/MAC** | 边界判断与输入/权重地址在每次 MAC 内重算；应做指针游走 + 常量提升 + 边界外置 | ★★★ 最高 |
| `_gen_conv` 无 pad 通用路径（1915–1934） | ~10 条/MAC | 每 `ic` 重算 `ic*H*W`、`oc*C_in*K*K`、`ih_base*W+iw_base` | ★★★ |
| `_gen_gemm`（2322–2349） | **~15 条/MAC** | `i*K`/`j*K` 循环不变量每次重算、`K` 两次重载；FC1 的 K=53824 | ★★★ |
| `_gen_maxpool`（2183–2216） | ~18–20 条/窗口元素 | `ih/iw/偏移` 从零重算；指针游走可大幅下降 | ★★ |
| `_gen_sigmoid`（2403–2453） | ~18–22 条/元素 | 4 个常量在循环内重载；阈值比较树可外提 | ★★ |
| `_gen_relu`（2091–2111） | ~13–14 条/元素 | 载入/存储地址算两遍、`num_el` 每轮重物化 | ★ |
| `_gen_reshape`（2485–2501） | ~11 条/元素 | 纯拷贝（2471 总分配新 workspace）→ 可做**零拷贝/别名**，直接消掉整个循环 | ★★（结构性） |
| `RISCVEmitter` 助手（1171–1315） | — | `emit_li32` 已有 `compact_li32`；`emit_qmul_srai` 可换 `mulh` 化简；可在 `to_bytes` 前加**发射后窥孔**（现无此框架） | ★★ |
| `MemoryPlan`（1076–1161） | — | bump 分配、无复用/活跃性分析（影响体积与缓存，不直接降指令数） | ★ |
| `_infer_*` + `_generate_node` dispatch（505–666 / 1569） | — | 新增算子（Fwht/Spmm）的扩展点；PoC 补丁即落此 | 扩展必需 |

**补丁路径面（D18 定稿）**

- **ALLOW（可改）**
  - `scratchv/standalone/onnx_to_riscv_standalone.py` —— 编译主文件：`_gen_*`、`RISCVEmitter`、`_infer_*`、`_generate_node`。
  - `scratchv/standalone/**` 下**新增**的辅助模块（如自建窥孔/循环优化模块），供上者 import。
  - （可选）`scratchv/backend/const_merge.py` —— 仅当评测启用 `--const-merge` 才影响产物；本期默认不启用，暂列为"允许但默认不计分"。
- **DENY（不可改，命中即 `compile_error(stage=scope)`）**
  - `scratchv/standalone/benchmark.py`（`RV32EmulatorFast`/`PerfCounters`/`PROFILES` —— 分数来源）、`bench_report.py`、`rv32_bench.py`、`run_spike_bench.py`、`spike_sim.py`。
  - `scratchv/simulator/tinyfive.py`、`scratchv/simulator/rv32_emulator.py`、`scratchv/standalone/cache_model.py`（交叉校验用）。
  - `评测工具/verify_model.py`（在赛事仓，平台侧固定副本并校验哈希）。
  - `tests/**`、`Makefile`、`scripts/**`、`scratchv/ci/**`、`ci_models.json`、`benchmark_reports/**`。
  - `scratchv/optimizer/**`、`scratchv/ir/**`、`scratchv/frontend/**`、`scratchv/pass_interface.py`、`scratchv/backend/asm_peephole.py`（**不在生产路径上**，改了不影响生成码，禁止以免误导）。
- **执行**：`git apply` 前后校验 `git diff --name-only <baseline_ref>` 全部落在 ALLOW、且不含 DENY；测量阶段以可信副本为准（D19）。

## 三、测试设计

### 测试用例 1：补丁通过（快乐路径）

- **输入**：登录并入队的队伍，`/submit` 选 `fwht`，上传一个**合法且有效**的补丁（例如 FWHT 算子补丁 `poc_fwht/fwht_op.patch`）。
- **预期输出**：提交页不整页跳转，出现"评测编号 #N"；配额 +1；结果页终态 `accepted`，展示 `max_lsb=0`、patched vs baseline 指标表与加速比。
- **验证点**：`details.apply.files` 仅含 `scratchv/standalone/onnx_to_riscv_standalone.py`；`baseline_ref` 非空；榜单出现该队；`/frag/result` 终态后停止轮询。

### 测试用例 2：补丁越界 / 应用失败（`compile_error`）

- **输入**：分别提交 (a) 改 `scratchv/standalone/benchmark.py`（企图改计数）的补丁；(b) 上下文对不上、`git apply` 失败的补丁。
- **预期输出**：均 `compile_error`；结果页展示失败阶段（`stage=scope` / `stage=apply`）与 `log_tail`（转义）；不计入榜单。
- **验证点**：路径面校验拦截测量文件；`/api/result` 的 `verdict=compile_error`；无 500。

### 测试用例 3：正确性一票否决（`invalid`）与性能下降

- **输入**：(a) 一个能让代码更快但数值错的补丁；(b) 一个正确但更慢的补丁。
- **预期输出**：(a) `invalid`，置顶深红警告，隐藏得分列；(b) `accepted` 且 `score < 100`（`ratio < 1`），指标表正确标注慢于基线。
- **验证点**：`details.correctness.status == "FAIL"`；榜单过滤 `verdict=='accepted'`；(b) 的 `ratio.cycles < 1` 与 `score` 一致。

### 测试用例 4：配额与权限边界

- **输入**：某队刷到 99 次后再提交；未登录 / 未入队访问 `/submit`。
- **预期输出**：第 100 次 409 "今日配额已用尽，05:00（UTC+8）后恢复"；未登录 302→`/login?next=/submit`；未入队 403 引导去 `/team/join`。
- **验证点**：`/api/quota.used == 99`；**无 CSRF token 的 POST 返回 400**；配额重置点与榜单 `since` 一致。

### 测试用例 5：移动端 + 深色模式 + 可访问性（回归）

- **输入**：390×844 视口、系统深色，仅用键盘 Tab 完成"选题 → 选补丁文件 → 提交"。
- **预期输出**：单列堆叠、无横向溢出；深色 token 全部生效；控件有可见 focus、`aria-label`、disabled 态可读。
- **验证点**：深色截图无浅色残留；无 console 错误、无 404 资源。

## 五、风险与前置条件

| 风险 | 说明 | 处置 |
|---|---|---|
| **任意代码执行** | 应用并导入选手补丁 = 执行选手代码 | v1 受信运行；上线前必须 Docker 隔离（无网络、只读基线、CPU/内存/时间限额）——列入上线前置 |

| **基线漂移** | 依赖机器性能 | 基线在同一机器/同一 profile 预置并定期校准；或同次评测跑一次未打补丁基线 |
| **基线未冻结** | 主仓仍在演进（HEAD 会变） | **已定 D17**：`baseline_ref` 钉 `6fcb97b`，评测只用该版本 |
| **环境不可复现** | 3.8 venv 坏、`llvmlite` 缺失 | 固定 Python 3.11 + `PYTHONPATH=.`；上线镜像化 |

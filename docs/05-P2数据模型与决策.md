## 一、功能介绍

### 1.1 功能概述

P2 为平台引入**身份与组队**，把当前"队名即提交"的匿名态升级为有账号、有队伍的状态：

- **注册**：华师大在读学生用 邮箱 / 姓名 / 密码 建档（邮箱必填、学号可选），默认角色 `player`。
- **登录 / 退出**：以邮箱为账号登录；会话保持；导航栏由"登录"占位切换为用户名 + 退出。
- **建队**：未入队用户创建队伍，系统生成邀请码；创建者自动成为队长与首位成员。
- **入队 / 退队**：以邀请码为索引——成员凭邀请码加入；退队后恢复为未入队态，可再次凭邀请码加入新队。受"每队 1~3 人、每人限一队"约束。
- **我的队伍**：展示队名、邀请码、成员列表、今日配额 `x/99` 与我的提交表。

### 1.2 设计目标

- **最小可用**：只覆盖 `docs/02 §1.4` 所划的 S2 范围（最小注册登录 + User/Team + 邀请码），管理端封禁/重测仍属 v2。
- **零新依赖倾向**：优先用 Flask 内置 `session` + Werkzeug 密码哈希，避免为一件事引入 Flask-Login / Flask-WTF（除非决策另有要求）。
- **约束在数据层兜底**："每人限一队"用数据库唯一约束保证，不只靠业务代码。
- **向前兼容**：不破坏现有 `platform.db` 与 `/api/submit` 契约；新增表由 `create_all()` 增量创建。
- **可演进**：`role` 预留 `admin`，供 P4 管理端复用，不返工。

## 二、设计规范

### 2.1 数据模型（新增三表）

> **存储（v1，已定 D10 = 方案 B）**：**运行时**持久化仍走 SQLAlchemy + SQLite（`platform.db`），下表即 ORM 表结构（字段即列，A 表引用的 id 在应用层校验）。**仅 demo / 初始数据**放 CSV（`data/*.csv`），应用启动时若表为空则从 CSV 导入；后续再替换为真正的数据库。
> 文件规划：`data/demo_submissions.csv`（榜单演示数据，纳入版本控制）；P2 的 users/teams/team_members 运行时仍入 SQLite。

**`User`**

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `id` | Integer | PK | |
| `email` | String(120) | **unique**, not null, index | 登录账号；格式校验，不强制校内域（D3） |
| `student_id` | String(20) | unique, nullable | 学号，可选（填则唯一） |
| `name` | String(40) | not null | 真实姓名（去首尾空白） |
| `password_hash` | String(255) | not null | Werkzeug `generate_password_hash` |
| `role` | String(16) | not null, default `'player'` | `'player'` / `'admin'`（见 D8） |
| `created_at` | DateTime | default `utcnow` | |

**`Team`**

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `id` | Integer | PK | |
| `name` | String(60) | **unique**, not null | 队名，榜单公示用 |
| `invite_code` | String(12) | **unique**, not null, index | 邀请码（规则见 2.4） |
| `captain_id` | Integer | FK `user.id`, not null | 队长 |
| `created_at` | DateTime | default `utcnow` | |
| `disbanded_at` | DateTime | nullable | 解散占位（D5 定是否启用） |

**`TeamMember`**

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `id` | Integer | PK | |
| `user_id` | Integer | FK `user.id`, **unique**, not null | **唯一约束 = 每人限一队** |
| `team_id` | Integer | FK `team.id`, not null, index | |
| `joined_at` | DateTime | default `utcnow` | |

**约束规则**

- 每队成员数 1~3：在入队 API 内校验 `count(team.members) < 3`（数据层不再加触发器，SQLite 不便于表达）。
- 每人限一队：由 `TeamMember.user_id` 的 `unique` 强制。
- 队长即成员：建队时同时写入一条 `TeamMember`，不空设。
- 删除用户/队伍：v1 不做级联删除（无删除入口）。

### 2.2 认证机制

| 项 | 方案 |
|---|---|
| 会话载体 | Flask 内置 `session`（`itsdangerous` 签名 cookie，已随依赖安装） |
| 密钥 | `Config.SECRET_KEY`，取自环境变量 `PLATFORM_SECRET_KEY`，缺省给开发值并打警告日志 |
| 登录写入 | `session['uid'] = user.id`；`session.permanent = True` |
| 有效期 | `PERMANENT_SESSION_LIFETIME = 14 天` |
| 登录标识 | 以 **邮箱** 作为账号登录；学号仅作可选资料 |
| 密码存储 | `generate_password_hash(pw)` / `check_password_hash`，永不返回 hash |
| 访问控制 | 自写装饰器 `@login_required` / `@admin_required`，读 `session`；页面未登录 → 302 到 `/login?next=…`，API 未登录 → 401 |
| 依赖 | **不引入** Flask-Login（v1 状态简单，避免多余依赖） |

> 注：`app.py` 当前 `debug=True` 会 reload，内存态（限频计数）在重启后清空，符合开发预期。

### 2.3 注册字段与校验口径

| 字段 | 规则 | 失败文案（用户视角） |
|---|---|---|
| `email` | 基本邮箱正则，**必填**、唯一；作为登录账号 | "邮箱格式不对" / "该邮箱已注册" |
| `student_id` | 可选；填写时 `^[0-9]{6,12}$` 且唯一 | "学号格式不对，应为 6–12 位数字" / "该学号已注册" |
| `name` | 去空白后 1–40 字 | "请填写真实姓名（1–40 字）" |
| `password` | 长度 ≥ 8 | "密码至少 8 位" |
| `password2` | 与 `password` 相同（页面二次输入） | "两次输入的密码不一致" |

> 邮箱是否强制 `@stu.ecnu.edu.cn` 校内域 → **已定 D3：不强制**，仅校验格式。

### 2.4 邀请码与组队规则

- **字符集**：`ABCDEFGHJKLMNPQRSTUVWXYZ23456789`（剔除易混的 `0/O/1/I/L`）。
- **长度**：8；生成后与 `Team.invite_code` 比对，冲突则重生成。
- **大小写不敏感**：入队输入统一转大写后再匹配。
- **重置**：队长可重新生成（旧码立即失效）—— 见 **决策 D4**。
- **入队校验顺序**（任一不过即拒绝，给对应可操作文案）：
  1. 邀请码存在 → 否则 404 "邀请码无效，请向队长确认"；
  2. 当前用户未入任何队 → 否则 409 "你已在队伍 <队名>，每人只能加入一支队伍"；
  3. 该队人数 < 3 → 否则 410 "该队已满 3 人"。
- **建队校验**：用户未入队；队名唯一（≤60 字）。
- **退队（已定 D5）**：成员可退队，退队后恢复未入队态，可再凭**邀请码**加入新队。队长退队需先转让队长或解散队伍（v1 规则）：
  - 队伍仅剩 1 人（队长本人）退队 → 直接解散并释放邀请码；
  - 队伍多于 1 人时队长退队 → 需先指定新队长（`captain_id` 转移）再退出。

### 2.5 安全（对应风险 H5）

| 项 | 方案 |
|---|---|
| CSRF | 采用 **Flask-WTF `CSRFProtect`**：全局校验 POST/PUT/PATCH/DELETE；表单用 `{{ csrf_token() }}` 隐藏字段，htmx/AJAX 走 `X-CSRFToken` 请求头；校验失败 400。`/api/submit` 暂豁免（P3 接入提交页后补 token，见 D9） |
| 登录限频 | 内存计数：同一 `email`（或 IP）连续失败 5 次 → 锁 15 分钟，返回 429 "尝试过于频繁，请 15 分钟后再试" |
| 输出转义 | Jinja2 默认转义；P2 不含源码查看（源码转义归 P3 处理） |
| 会话固定 | 登录成功后 `session.clear()` 再写入，规避固定攻击 |
| 密码 | hash 存储；响应体不含 `password_hash` |

> CSRF 采用 Flask-WTF（决策 D6）；需配置 `SECRET_KEY`（用于会话签名与 token 签名）。

### 2.6 API 契约（沿用 `docs/01 §2.6`，此处补响应体）

| 方法 | 路径 | 请求体 | 成功 | 失败 |
|---|---|---|---|---|
| POST | `/api/auth/register` | `{email,name,password,student_id?}` | 201 `{user:{id,name,role}}` | 400 `{error}` |
| POST | `/api/auth/login` | `{email,password}` | 200 `{user}` | 401 / 429 `{error}` |
| POST | `/api/auth/logout` | — | 204 | — |
| GET | `/api/me` | — | 200 `{user, team \| null, quota:{used,limit,reset_at}}` | 401 |
| POST | `/api/team` | `{name}` | 201 `{team:{id,name,invite_code}}` | 409 `{error}` |
| POST | `/api/team/join` | `{invite_code}` | 200 `{team}` | 404/409/410 `{error}` |
| POST | `/api/team/leave` | — | 204 | 409 `{error}` |

**页面路由**（复用 `base.html`，htmx 局部提交，失败不跳转）：

| 路径 | 页面 | 访问 |
|---|---|---|
| `/register` | 注册表单 | 访客 |
| `/login` | 登录表单（支持 `?next=`） | 访客 |
| `/team` | 我的队伍工作台（成员 / 邀请码 / 配额 / 我的提交） | 登录 |
| `/team/join` | 建队或凭码入队 | 登录 |

**导航联动**：`base.html:57` 的"登录"占位替换为登录态；`base.html:92,95` 的「提交」「我的队伍」由 disabled 启用。

### 2.7 角色与权限

- `role` 取值：`player`（默认）/ `admin`。
- **队长不是独立角色**，由 `Team.captain_id` 派生；权限矩阵中"队长"能力 = `player` + 本人是 captain。
- 权限沿用 `docs/01 §2.2` 矩阵；P2 只落地"访客 / 选手 / 队长"三档，`admin` 仅建模不分发页面。
- 「评委」角色（风险 M6）→ **决策 D8**。

### 2.8 与现有 `/api/submit` 的衔接

现状：`/api/submit` 从表单取裸 `team` 字符串写 `Submission.team_name`。P2 建议改为：

```
team_name = 当前登录用户所属队伍名  (已登录且已入队)
          ← 回退 →  表单 team 字段  (未登录/未入队)
```

理由：不破坏现有契约与演示数据（`docs/02 §1.4`"登录先用队名即提交过渡"），P3 重写提交页与评测口径时再收紧为"必须登录"。→ **决策 D9**。

## 三、测试设计

### 测试用例 1：注册 → 登录 → 会话

- **输入**：`POST /api/auth/register` `{student_id:"10240001", name:"张三", email:"zs@stu.ecnu.edu.cn", password:"pass1234"}`；随后 `POST /api/auth/login` `{identifier:"10240001", password:"pass1234"}`；再 `GET /api/me`。
- **预期输出**：注册 201；登录 200 且带 Set-Cookie；`/api/me` 200 返回 `user.name=="张三"`、`team==null`。
- **验证点**：重复学号注册返回 400 且提示"已注册"；错误密码返回 401；连续 5 次失败后第 6 次返回 429。
- **Playwright**：`/register` 表单提交后不整页跳转；导航栏出现用户名。

### 测试用例 2：建队 → 邀请码入队 → 上限与唯一性

- **输入**：用户 A `POST /api/team {name:"编译先锋"}` 取 `invite_code`；用户 B、C、D 依次 `POST /api/team/join {invite_code}`。
- **预期输出**：B、C 入队成功（队员数 2→3）；D 返回 410 "该队已满 3 人"；A 再次建队返回 409；A 尝试 join 返回 409 "每人只能加入一支队伍"。
- **验证点**：`TeamMember.user_id` 唯一约束在第二次入同一队/他队时报错并转成 409；`GET /api/me` 的 `team.name`、成员数正确。

### 测试用例 3：鉴权与 CSRF 边界

- **输入**：未登录 GET `/team`；未带 CSRF token 的 `POST /api/team`；登录后正常带 token 的 `POST /api/team`。
- **预期输出**：未登录页面 302 → `/login?next=/team`，API 401；缺 CSRF 400；带 token 201。
- **验证点**：`session.clear()` 后旧 session 不残留用户；响应体不含 `password_hash`。

# 收紧仓库 push 权限（禁止直接推 main）

## 现状

- 仓库 `ScratchV-Compiler/riscv-ai-compiler-platform` 为 **public**、允许 fork。
- **没有任何 ruleset**（`GET /repos/.../rulesets` 返回空数组）⇒ 目前**有写权限的人都能直接 push `main`**。

## 做法：给 main 加一条 Ruleset（推荐，可一键导入）

Ruleset 比老的 Branch protection rule 更好用：一次配置可覆盖多个分支，界面也更清晰，
且 GitHub 支持**从 JSON 文件导入**。

**导入步骤**

1. 打开 `https://github.com/ScratchV-Compiler/riscv-ai-compiler-platform/settings/rules`
2. 点 **New ruleset → Import a ruleset**
3. 选本仓库的 `docs/rulesets-protect-main.json` 上传 → **Create**

导入后 `main` 的规则变成：

| 规则 | 效果 |
|---|---|
| `pull_request`（required_approving_review_count = 0） | **只能通过 Pull Request 改动** → 直接 `git push origin main` 被拒 |
| `deletion` | 禁止删除 `main` |
| `non_fast_forward` | 禁止强推覆盖历史 |

> **为什么审批数是 0**：GitHub **不允许自己批准自己的 PR**。若要求 ≥1 个审批，单人维护时会把自己卡死。
> 置 0 的含义是"**改动必须走 PR 流程**"，但你仍可自行合并 ✓。
> 组织里若还有人参与评审，再把它改成 1 即可。

> **若你想保留自己的"紧急直推"能力**：在 ruleset 的 **Bypass list** 里只加 `Repository admin`。
> 我给的 JSON 里 `bypass_actors` 为空 = **谁都不能直推**（最严格）。按需自行添加。

## 同时建议：收一收"谁能推"

Settings → **Collaborators and teams**（组织仓库在 **People / Teams with access**）：
把不该有写权限的人降为 **Read** 或移除。Ruleset 管的是"怎么推"，这里管的是"谁能推"。

## 可选：把非默认分支也一并保护

上面的 JSON 用 `~DEFAULT_BRANCH`（只保护默认分支 `main`）。
如需连 `seven01` 等历史分支一起锁，把 `conditions.ref_name.include` 改成：

```json
"include": ["~ALL"]
```

## 对自动部署有没有影响？—— **没有**

`.github/workflows/pages.yml` 只做两件事：**读取仓库**（`contents: read`）+ **发布到 Pages 环境**。
它**不往 `main` 推任何东西**，所以加规则后自动部署照常工作 ✓。

新流程变成：

```
改代码 → 推到功能分支 → 开 PR → 合并进 main → 自动重建并发布静态站
```

这是**唯一**多出来的一步（开 PR 并合并）。
